# 都市計画基礎調査 オープンデータ収集ツール

全国の都市計画基礎調査データをオープンデータカタログから収集し、Web 地図化するための土台。
現時点では **収集フェーズ（harvest / fetch）** が動く。

## 都市計画基礎調査とは

都市計画法第 6 条に基づく法定調査。条文上の実施主体は **都道府県**：

> 第六条　**都道府県は**、都市計画区域について、おおむね五年ごとに、都市計画に関する基礎調査として、
> 国土交通省令で定めるところにより、人口規模、産業分類別の就業人口の規模、市街地の面積、土地利用、
> 交通量その他国土交通省令で定める事項に関する現況及び将来の見通しについての調査を行うものとする。
>
> ３　都道府県は、前二項の規定による基礎調査を行うため必要があると認めるときは、
> **関係市町村に対し、資料の提出その他必要な協力を求めることができる。**

市町村は第 3 項の「協力」として実務の相当部分を担う。実際、静岡県はデータセットの説明文で
「建物利用調査は都市計画法第 6 条第 3 項に基づき対象市町が調査している」と明記し、
問い合わせ先を市町に振っている。つまり **法的な実施主体は都道府県、実務の担い手は市町村** という
二層構造になっており、公開元もその両方に散らばる。これが収集を面倒にしている根本原因。

出典: 都市計画法（昭和四十三年法律第百号）第 6 条 / e-Gov 法令 API `343AC0000000100`

## データの所在（実測）

**全国を 1 つの API で舐める手段は存在しない。** 実測した結果：

| カタログ | 総データセット | 基礎調査 |
|---|---:|---:|
| G空間情報センター | 17,274 | 56 |
| 岐阜県オープンデータ | 1,879 | 81 |
| BODIK ODCS（約350自治体） | 18,311 | 23 |
| 山口県オープンデータカタログ | 770 | 18 |
| 神奈川県オープンデータカタログ | 807 | 3 |
| 東京都カタログ | 9,648 | 2 |
| 横浜市 | 657 | 1 |
| data4citizen | 411 | 1 |
| 札幌 / 仙台 / 宇都宮 / 港区 / 那須 / 加古川 ほか | — | 0 |
| e-Gov（旧 data.go.jp） | 18,144 | 0（府省庁のみ） |

対象カタログは `search.ckan.jp`（データカタログ横断検索システム）の
[サイト一覧](https://search.ckan.jp/sites) を起点に実測して積み上げた。

G空間情報センター上の基礎調査データは **全件が自治体発**（静岡県・大分県・さいたま市・
埼玉県・越谷市・伊奈町）。`都市局` 名義で載っているのは `全国都市計画決定情報GIS` という
別データで、これは基礎調査ではなく**決定情報**（基礎調査を基に決定された内容の側）。

国土交通省のオープン化ページにある CSV は **全国データではなく様式テンプレート**
（実測 668 バイト・4 行、和名ヘッダ＋英名ヘッダのみ）。`lui_201`〜 のような標準列名が
定義されており、変換フェーズの列マッピングに使える。

### 結論

「全国」に到達するには CKAN 横断だけでは足りない。**カタログ登録簿（`catalogs.yaml`）と
非CKANサイト登録簿（`sites.yaml`）を実測しながら育てる**のが唯一の現実解。

## 使い方

```bash
pip install -e .          # または PYTHONPATH=src で直接実行

bskp probe                     # カタログの疎通確認
bskp discover candidates.txt   # 候補URLがCKANとして使えるか実測（1行1URL）
bskp harvest                   # CKAN横断検索 → data/inventory/resources.csv
bskp harvest --limit 0         # 上限なしで全件走査
bskp scrape                    # 非CKANサイトを走査 → data/inventory/scraped.csv
bskp report                    # インベントリを集計（両方まとめて）
bskp fetch --kind geo          # 実ファイルを取得 → data/raw/
bskp fetch --dry-run           # URLと保存先を出すだけ

# 走査ログは logs/bskp.log に追記される（--log で変更可）
```

## 設計メモ

**検索は広く、絞り込みはクライアント側で。** CKAN の Solr は日本語トークナイズ設定が
インスタンスごとに違い、同じクエリでも挙動が揃わない。

- G空間情報センター: `都市計画基礎調査` → 55 件、`"都市計画基礎調査"` → 23 件（フレーズ検索の方が少ない）
- BODIK: 前者 4,781 件（ほぼ全件でノイズ）、後者 23 件
- 東京都: 前者 2,832 / 9,648 件（＝実質全件マッチ）

そのため複数クエリを投げて OR で束ね、`title` / `notes` / `tags` に
`都市計画基礎調査` が現れるかで最終判定する。BODIK は全 4,781 件を走査しても該当 23 件で、
上限 2,000 件による取りこぼしは実測ゼロだったが、設計上は危ういので
打ち切り時に WARNING を出す（`--limit 0` で無効化）。

**「基礎調査」を名乗らない出し方がある。** 東京都は同じものを
「土地利用現況調査GISデータ」として公開しており、メタデータに「都市計画」の語が一切ない
（説明は「東京都における土地利用現況調査の結果をGISデータで作成したものです」だけ）。
そこで実施要領の調査項目名（土地利用現況調査 / 建物利用現況調査）でも拾い、
その経路で拾ったものは `resources.csv` の `match` 列に `alias` と記録して後から外せるようにする。

**接続まわりはカタログごとに癖がある。** `catalogs.yaml` で個別に上書きする。

- `user_agent`: G空間情報センターの WAF は見慣れない UA を 403 で弾く
  （`curl/*`・`python-requests/*`・ブラウザ UA は通る）。検索とダウンロードの両方に効く
- `legacy_tls`: 山口県は OpenSSL 3 の既定 SECLEVEL=2 に鍵長が届かず
  `TLSV1_ALERT_INSUFFICIENT_SECURITY` になる。curl では通るので原因が分かりにくい

**一部カタログだけ走査しても他を消さない。** `--catalog` 指定時は既存インベントリの
残りをマージしてから書く。走査に失敗したカタログの結果を空で上書きしないため。

**走査ログを残す。** `logs/bskp.log` に時刻付きで追記する。提供側の公開状況は動くので、
取れなくなったときに前回との差分が要る。山口県の SSL エラーもログから特定した。

**再実行は差分だけ。** `data/raw/manifest.jsonl` に sha256 付きで記録し、
取得済みは飛ばす。失敗記録は次回再試行される。

## Web 地図化に向けた既知の課題

1. **座標系がバラバラ。** 平面直角座標系で配布される（日田市は JGD2000 / Japan Plane
   Rectangular CS II = EPSG:2444）。系番号は県ごとに違うので `.prj` を見て
   `-t_srs EPSG:4326` で個別に再投影する。
2. **ZIP の中身は開くまで分からない。** 556 件の ZIP は SHP・PDF・調書が混在する。
   静岡県の ZIP は入れ子（ZIP の中に ZIP）。インベントリの `kind=archive` は
   「要展開・要判定」の意味。
3. **リソースの format 表記が当てにならない。** 大分県玖珠町の「shpデータ」リソースは
   実体が CSV のみ（URL も csv 版と同じ `oitakenkusucsv.zip`）。format ではなく
   中身で判定する必要がある。
4. **文字コードと ZIP 内ファイル名。** DBF は CP932、ZIP エントリ名も CP932。
   Python の `zipfile` は cp437 として読むので明示的に再デコードする。
5. **粒度が違う。** 小地域単位のポリゴン（日田市の土地利用現況は 116 フィーチャ）と、
   建物単位のデータが混在する。凡例・ズームレベル設計に影響する。
6. **ライセンスが不統一。** CC-BY / GNU FDL / 独自利用規約 が混在。
   `resources.csv` の `license` 列に保持している。

## 構成

```
catalogs.yaml            CKANカタログの登録簿（20件・うち18有効）
sites.yaml               CKANを持たない配布サイトの登録簿
candidates.txt           discover に食わせる候補URLリスト
src/bskp/
  ckan.py                CKAN クライアント（ページング・リトライ・UA/TLS切替）
  harvest.py             横断検索とクライアント側フィルタ
  scrape.py              非CKANサイトのリンク抽出（robots.txt尊重・文字コード判定）
  fetch.py               ダウンロード（sha256・レジューム）
  cli.py                 probe / discover / harvest / scrape / report / fetch
data/
  inventory/             datasets.jsonl, resources.csv, scraped.csv（git 管理）
  raw/                   取得した実ファイル（git 管理外）
logs/bskp.log            走査ログ（追記）
```

## 非CKANサイトについて

`bskp scrape` はページの `<a href>` からデータファイルへのリンクを拾う。
robots.txt を必ず確認し、1ドメイン直列・ウェイト付きで、`follow` は 1 段だけ。
無制限クロールはしない。

実測でわかった型：

- **通常の市ページから直接配布**（津島市）— 18リンク取得。この型は全国に多数ある
- **文字コードが揺れる** — requests は charset 未指定の text/html を ISO-8859-1 と
  決め打ちするため、そのままだとリンク文字列が化ける。meta charset →
  バイト列推定 → UTF-8 → CP932 の順に試す
- **ログインが要る**（広島県 DoboX）— CKAN API は無く内部 API は 401。
  一覧も動的描画。匿名では取得できないので `enabled: false` にしてある
- **JS 描画で静的HTMLにリンクが無い**（静岡県）— 0件。ブラウザ自動化が要る
